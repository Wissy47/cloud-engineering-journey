# Week 3 — Day 7: EC2 Mini Project

## Objective

Combine the major EC2 concepts learned during Week 3 into one practical architecture and validate the environment.

The project covered:

* EC2 lifecycle
* AMIs
* Instance types
* User Data
* EBS storage
* Persistent filesystems
* ENIs
* Private and public addressing
* IAM roles
* Instance profiles
* Instance metadata
* Backup and recovery concepts
* Private EC2-to-EC2 communication

```text
VPC

    ├── EC2 Web Server
    │   ├── Ubuntu ARM64 AMI
    │   ├── t4g.micro
    │   ├── Security Group
```

## Compute Validation

The instance remained operational and preserved its configuration across lifecycle operations.

The primary private IP remained stable during stop/start testing.

Key lifecycle rule:

```text
Reboot
→ same ENI
→ same private IP
→ auto-assigned public IP normally remains

Stop / Start
→ same primary ENI
→ same private IP
→ auto-assigned public IP may change
```

## Storage

The root EBS volume was:

```text
vol-57d7a864d29ad9cf6
```

with:

```text
DeleteOnTermination: true
```

This means the root volume is intended to be deleted when the instance is terminated.

A separate EBS volume was also created during Week 3:

```text
vol-a8d611b531a752583
```

Floci exposed the attachment in metadata but did not expose it as a real Linux block device.

A loop-backed filesystem was therefore used to practice:

* `mkfs.ext4`
* `mount`
* `umount`
* UUIDs
* `/etc/fstab`
* data persistence

## AMI and Recovery

A custom AMI was created:

```text
ami-19e6ea348547095a9
```

Name:

```text
week3-day4-cloud-lab-ami
```

A new EC2 instance was successfully launched using that AMI.

However, Floci did not reproduce the original instance filesystem changes in the new instance.

This differs from real AWS, where EBS-backed AMIs use snapshots to preserve disk state.

## Snapshot Strategy

Floci did not support:

```bash
aws ec2 create-snapshot
```

but the real AWS recovery model was studied:

```text
EBS Volume
↓
Snapshot
↓
Replacement EBS Volume
↓
Attach
↓
Mount
↓
Recover data
```

Key distinction:

```text
EBS Snapshot
→ storage recovery

AMI
→ server reproduction

AMI + EBS snapshots
→ server + data recovery
```

## Instance Metadata

The standard real AWS metadata address is:

```text
169.254.169.254
```

The instance reported metadata configuration as enabled, but Floci did not provide a functioning IMDS endpoint.

In real AWS:

```text
EC2
↓
Instance Profile
↓
IAM Role
↓
IMDS
↓
temporary credentials
↓
AWS SDK / CLI
```

## Floci Limitations Discovered

The lab identified several differences from real AWS:

* Docker-backed private IPs instead of subnet CIDR addresses
* incomplete Elastic IP association metadata
* secondary private IP assignment unsupported
* standalone ENI creation unsupported
* EBS snapshot API unsupported
* attached EBS not exposed as a real Linux block device
* custom AMIs did not preserve runtime filesystem changes
* instance-profile association unsupported
* IMDS endpoint not fully implemented

These limitations were documented separately from real AWS behavior.
